# GoNavi 本地密码本需求与交互规格

- 整理日期：2026-10-05
- 阶段：需求与交互已梳理，技术方案 v1.0 已整理；见 [technical-design.md](./technical-design.md)，尚未开发或完成工程验证
- 性质：仅供当前 clone 本地讨论，不进入产品分支或上游 PR
- 说明：“已确认”来自本次讨论；“默认方案”由产品设计补充，尚未通过页面原型或人工试用验证。

## 1. 背景与目标（已确认）

用户的 API Key、Token、云服务凭据、平台账号、数据库和服务器信息散落在项目、配置、聊天记录等位置，时间久了难以找回，也缺少用途、有效期及变更记录。

提供统一的本地入口，让用户主动保存、快速找到、查看和复制这些信息。保存记录不要求 GoNavi 能连接或使用对应服务。

典型场景：

1. 按 DeepSeek、Kimi 等平台找到多个不同账号或用途的 Key。
2. 找到云服务 SDK、CLI、API 所需的一组凭据。
3. 找到内网数据库信息，即使当前网络无法访问，也可以正常保存和复制。
4. 管理多台服务器的连接信息。
5. 找回修改前的内容，并恢复为新的当前版本。

核心目标：集中保存、快速检索、便捷取用、本地加密、历史可追溯。

## 2. 首版范围

### 2.1 已确认的能力

- 创建多个密码本，与数据库连接处于同一导航层级。
- 每个密码本包含内置类型；支持用户创建自定义类型和字段。
- 记录的新增、查看、编辑、删除、搜索与筛选。
- 秘密字段默认隐藏，支持主动查看和复制。
- 秘密复制后的剪贴板自动清理可配置，用户决定是否启用及清理等待秒数；只清理仍为本次复制的内容，不覆盖用户随后复制的内容。采用默认启用、30 秒，可由用户调整；实际清理能力需跨平台验证。
- 按类型提供不同的表单、列表列和专属操作。
- 复制为新记录；数据库按格式复制连接字符串。
- 历史版本查看、差异比较、恢复；恢复时新增版本，不截断历史。
- 用户维护使用状态，并记录有效期。
- 部分类型支持创建时自动验证一次，后续手动重测。
- 大模型验证允许最小推理请求。
- 对具备入口的类型提供浏览器跳转。
- 所有记录内容和历史本地加密保存，密钥自动管理，不要求额外记住主密码。
- 首版搜索范围限制为当前密码本。

### 2.2 不纳入首版的能力（已确认）

- 云端保存、同步或托管。
- 加密备份、导入导出、跨设备迁移、局域网同步；作为后续版本目标。
- 自动扫描项目、配置、聊天记录或主动获取平台凭据。
- 密码本凭据与 GoNavi AI 配置、数据库连接的自动联动。
- SSH 终端或完整远程服务器工作台；服务器验证不包含远程操作。
- 自动填充网页、自动登录平台。
- 打开密码本时批量测试、周期巡检或后台定时验证。
- 企业共享、角色权限、远程撤权、自动轮换凭据。

## 3. 信息结构（已确认）

| 概念 | 产品含义 | 数据库类比 |
| --- | --- | --- |
| 密码本 | 用户命名的独立容器，例如个人、工作、客户 A | 数据库 |
| 类型 | 内置模板或用户自定义的记录结构 | 表 |
| 记录 | 一组用于某个账号或用途的信息 | 行 |
| 字段 | 地址、账号、密码、有效期等 | 列 |

此类比用于产品理解，不预先规定实际数据库表结构。

- 一条记录属于一个密码本、一个类型。
- 同一平台、账号、类型可以保存多条不同用途的记录。
- 平台是检索维度，不强制成为另一级导航树。
- 密码本不强制按个人、公司或平台划分，用户自由命名。
- 内置类型不允许用户追加、删除、改名或调整字段定义；保留备注字段。
- 自定义类型创建后，与内置类型并列显示。
- 官方类型定义、厂商预设、管理地址、验证规则等由 GoNavi 统一维护，不复制进每个密码本。密码本只保存所需的稳定引用标识及用户内容。
- 用户创建的自定义类型及字段定义属于用户数据，应随其密码本保存；必要的文件格式版本等技术元信息仍需保留。

## 4. 内置类型与能力

| 类型 | 定位 | 首版验证 | 浏览器操作 |
| --- | --- | --- | --- |
| 大模型 API Key | 大模型平台和自定义中转站的调用凭据 | 按适配平台或协议执行基础检查，必要时最小推理请求 | 内置平台提供“打开平台” |
| 云服务凭据 | 云厂商不同形式的密钥或临时凭据 | 首版仅记录，不验证 | 内置厂商提供“打开平台” |
| 数据库 | 数据库连接和认证信息 | 使用受支持的连接方式验证 | 无默认专属入口 |
| 服务器 | 服务器连接和认证信息 | 默认方案：首版验证 SSH 密码认证 | 无默认专属入口 |
| 平台账号 | 网站或应用账号 | 不验证 | 有有效登录地址时提供“打开登录页面” |

用户创建的自定义类型首版不提供自动或手动连接验证。

### 4.1 公共字段与元信息（默认方案）

- 名称：必填，用于辨认同平台下不同记录。
- 账号标识或所属账号：相关类型提供，用于区分个人、工作等账号。
- 用途：记录项目、环境或用途，参与搜索。
- 使用状态：在用、停用、作废。
- 有效期：明确日期、长期或未知。
- 备注：多行文本。
- 系统维护创建时间、内容修改时间、当前版本。
- 支持验证的记录另有验证时间、检查范围、结果和原因。

字段显示、必填条件随类型确定；不为没有实际用途的类型强塞同一套表单。

### 4.2 大模型 API Key

- 平台：共用现有 AI 厂商预设，包含 DeepSeek、Kimi、小米 MiMo 等及自定义平台。
- 根据厂商提供服务模式选项，例如普通 API、Coding Plan。
- 使用预设的 API 地址、协议及认证方式。
- 内置平台自动提供默认配置；确有多种地址或协议时提供必要选择。
- 自定义平台填写名称、API 地址，选择已支持协议。
- 保存 API Key，以及名称、账号标识、用途、有效期、状态、备注。
- 验证需要指定模型时，优先使用合适的内置测试模型；没有合适默认值时提供“验证模型”选项。
- 缺少测试所需配置不阻止保存。
- 平台管理地址由 GoNavi 内置维护，不作为用户可见或可编辑字段。
- 自定义平台无法确定管理地址时，不提供跳转按钮，不从 API 地址猜测控制台地址。

### 4.3 云服务凭据

- 内置厂商选择，并由凭据种类决定固定表单。
- 默认方案：首版优先覆盖常见长期密钥对、单值 Token、附带 Token 的临时凭据。
- 根据厂商使用恰当字段名称，例如 AccessKey ID / Secret、SecretId / SecretKey。
- 不承诺覆盖厂商的所有认证方式；准确的厂商与凭据种类清单在技术调研时核实。
- 平台管理地址内置维护，用户通过“打开平台”自行登录、查看或创建凭据。
- 不提供验证按钮，不发起创建后的测试请求。

### 4.4 数据库

- 数据库类型、地址、端口、数据库名或相应目标、用户名、密码。
- 类型决定必要的专属选项；密码等字段按数据库实际认证方式确定必填条件。
- 支持复制地址、端口、用户名、密码、数据库名等适合取用的字段。
- 支持“复制连接字符串”，格式按数据库及目标客户端区分。
- 默认方案：首版提供少量常见格式，记住上次选择；包含密码的选项明确标识。
- 保存范围可以宽于当前可验证范围；驱动或必要连接配置缺失时仍可记录。
- 当前网络访问不到内网数据库，不影响保存和取用。

### 4.5 服务器

- 地址、协议、端口、用户名、认证信息、用途、备注。
- 默认方案：首版以账号密码记录为主要模板，SSH 密码认证提供验证。
- RDP 或其他协议可记录，但首版不做认证验证。
- 技术方案首版采用用户名/密码模板与 SSH 密码验证；专用私钥字段及加密私钥认证留到后续版本。用户自定义秘密字段可保存其他文本凭据。
- SSH 验证完成后关闭连接，不执行命令，不打开终端。
- 沿用现有服务器身份确认流程，不能用端口连通代替账号认证通过。

### 4.6 平台账号

- 平台名称、账号、密码、可选登录地址，以及公共记录信息。
- 不增加“是否 Web 服务”字段。
- 有有效网页登录地址时显示“打开登录页面”；未填写时不显示。
- 浏览器只打开目标页面，不填充或传递账号密码。

## 5. 页面结构与主要交互

### 5.1 导航（已确认）

```text
连接列表
  MySQL · 开发库
  Redis · 缓存
  密码本 · 个人
    全部记录
    大模型 API Key
    云服务凭据
    数据库
    服务器
    平台账号
    软件许可证          ← 自定义类型示例
    ＋ 新建类型
  密码本 · 工作
    …
```

- 密码本与数据库连接同级，使用不同图标。
- 默认方案：双击“打开”，展开分类；右键提供重命名、关闭、删除等管理操作。
- 创建密码本只填写名称等必要信息，不呈现主机、端口、连接测试表单。
- 密码本打开与记录验证是两件事；打开不会触发记录测试。
- 分类显示记录数量；“全部记录”表示当前密码本内的全部类型。

### 5.2 记录列表与详情（已确认的方向，细节为默认方案）

- 沿用 GoNavi 工作区标签页与主题。
- 首版密码本工作区限定桌面主窗口，详情抽屉和编辑弹窗正常支持；分离为独立系统窗口列为后续目标，避免接入现有 HTTP 桥。
- 点击类型后，主工作区显示完整宽度的记录列表。
- 列表顶部提供搜索、适用筛选、新建按钮。
- 各类型使用适合自己的列；全部记录视图显示公共字段及类型。
- 单击选中记录；点击“详情”或双击打开右侧详情抽屉。
- 列表提供适合该类型的常用操作，例如复制密钥。
- 详情抽屉提供“当前内容”和“历史版本”页签。
- 关闭详情后保留搜索、筛选、选中项及滚动位置。
- 不常驻第三栏，不把全部字段塞进列表。

### 5.3 搜索与筛选

- 首版只搜索当前密码本，不跨密码本。
- “全部记录”可跨当前密码本内的类型搜索。
- 支持名称、平台、账号、地址、用途、备注等非秘密内容检索。
- 默认不搜索密码、Key、Secret 的内容。
- 提供平台、使用状态等适用筛选；有效期及验证结果按类型提供。
- 默认方案：首次打开显示全部记录；默认按平台、名称排列，并支持按修改时间排序。

### 5.4 新增与编辑

- 从类型页面新建时预选类型；全部记录页面新建时先选择类型。
- 保存前校验必要字段，保存动作明确，不静默覆盖。
- 测试所需信息不足与存储必填项不足分开处理。
- 仅实际内容变化生成版本，重复保存不生成空版本。
- 未保存内容离开时提示保存或放弃。

### 5.5 复制与跳转

- “复制字段”：字段旁按钮复制单个值；复制秘密不要求先显示明文。
- “复制连接字符串”：数据库专属操作，选择受支持格式，正确处理特殊字符。
- “复制为新记录”：打开预填的新建表单，确认保存后才创建独立记录。
- 复制新建不继承历史、验证结果和系统时间，新记录从 V1 开始。
- 默认方案：名称添加“副本”，使用状态默认在用，提醒用户检查带入的凭据和有效期。
- 复制创建成功后，按新记录规则发起首次验证。
- 浏览器跳转使用系统默认浏览器，按钮位置与风格保持一致。
- 内置平台管理地址由公共目录维护，用户只看到操作按钮。

### 5.6 删除（默认方案）

- 删除记录前说明将删除当前内容及全部历史，并要求确认。
- 删除自定义类型前说明其记录数量和影响范围；内置类型不可删除。
- 删除密码本前显示范围并要求输入名称确认。
- 首版不另设回收站；删除不可恢复，历史恢复仅适用于仍存在的记录。
- 密码本“关闭”与“删除”使用不同操作，关闭不删除数据。

## 6. 自定义类型（已确认能力，规则为默认方案）

- 用户填写类型名称，定义字段名称、类型、顺序、必填条件和可选默认值。
- 首版字段类型：文本、秘密、多行文本、数字、日期。
- 秘密字段决定隐藏、查看、复制行为，所有字段仍加密保存。
- 不支持公式、脚本、关联表、用户自定义 HTTP 验证流程。
- 已有记录使用的字段，首版不允许直接删除或更改数据类型；允许改名、排序及追加字段。
- 追加必填字段不影响旧记录读取，旧记录下次编辑保存时补齐。
- 类型结构变更不能破坏历史版本的展示和整条恢复；具体实现留到技术阶段。

## 7. 使用状态与有效期（已确认）

### 7.1 使用状态

| 状态 | 含义 |
| --- | --- |
| 在用 | 当前准备使用，新建默认 |
| 停用 | 暂时不用，可能重新启用 |
| 作废 | 已被替换或不再使用，保留备查 |

状态由用户维护，不代表真实服务状态。标记作废不会向厂商撤销密钥。状态变化属于内容修改，进入历史。

### 7.2 有效期

- 用户选择明确日期、长期或未知。
- 有明确日期时计算未到期、即将到期、已到期。
- 默认方案：七天内到期显示即将到期，按用户本地日期判断。
- 有效期不自动改变使用状态；首版不提供后台到期通知。

## 8. 历史版本与恢复（已确认）

- 创建记录产生 V1；每次有效内容保存产生下一版本。
- 历史保存当时的完整记录内容，而非仅保存密码变化。
- 展示版本、保存时间、操作类型、修改字段；可以查看完整内容及相邻版本差异。
- 秘密字段的当前值、旧值均默认隐藏，可主动查看和复制。
- 恢复旧版覆盖当前记录的可编辑内容，并生成新的版本。
- 不删除恢复目标之后的版本，不生成另一条业务记录。
- 恢复保留记录身份、原创建时间，内容修改时间记为本次恢复时间。
- 恢复可编辑的状态、有效期、备注等，不恢复旧的验证结果。
- 不能通过记录恢复修改真实平台、数据库或服务器的凭据。
- 默认方案：不因时间或版本数量自动截断历史；重复保存相同内容不新增版本，恢复目标与当前内容一致时提示无需恢复。

示例：V1 → V2 → V3 → V4，恢复 V2 后生成 V5；V1—V4 全部保留，V5 内容与 V2 相同，并标注“恢复自 V2”。

## 9. 验证规则（以最新讨论为准）

### 9.1 触发时机

1. 新记录保存成功后，对具备验证能力且信息完整的记录自动执行一次。
2. 验证异步进行，不阻塞保存；失败不撤回记录。
3. 后续通过“重新验证”按钮发起；打开密码本或查看记录不自动测试。
4. 修改或恢复测试相关字段后标记“配置已变更，需重新验证”，不自动发起。
5. 仅改名称、用途或备注，不使结果失效。
6. 支持取消，不进行周期、批量或后台巡检。

### 9.2 验证范围

- 大模型：优先适合的官方基础接口；必要时允许最小推理请求，尽量限制调用量。界面简短说明可能产生少量调用费用。
- 基础接口与推理测试都要明确结果实际覆盖的范围，不把一次通过解释为所有模型、业务权限可用。
- 云服务凭据、平台账号、自定义类型首版不验证。
- 数据库：连接和认证，使用临时连接并释放，不修改数据，不验证所有表的读写权限。
- 服务器：默认方案为 SSH 密码认证，不执行命令或建立工作会话。
- 不支持的协议、缺失配置、缺失驱动等显示无法验证，不影响保存。

### 9.3 结果表达

| 结果 | 表达 |
| --- | --- |
| 未测试 | 具备验证能力但尚无检查结果 |
| 测试中 | 当前请求进度，可取消 |
| 验证通过 | 显示检查范围和时间 |
| 验证失败 | 认证拒绝等明确失败，展示原因 |
| 无法验证 | 不支持、网络不可达、超时或信息不足等，展示原因 |

- 超时或当前网络不可达不等于凭据错误。
- 不支持验证的类型不显示可点击的测试按钮；详情可说明不支持。
- 列表及详情称“上次验证”，保留时间，不能把缓存结果当作实时状态。
- 修改测试相关字段后，旧结果可以展示为历史参考，但不能继续标为当前配置通过。
- 测试期间配置改变或记录删除，不把旧请求结果写为新配置的验证结果。
- 验证结果独立于使用状态、有效期和内容版本；重测不新增内容版本。

## 10. 本地保护与产品承诺

- 安全性是存储选型的首要依据，开发便利和已有依赖只能作为次要因素；对当前、历史、索引、日志和临时文件的保护边界都应有验证证据。
- 当前内容、历史内容及敏感备注均加密后落盘，用户无需手动管理加密密钥。
- 采用每本独立 SQLCipher 文件和随机密钥，由系统安全存储保管；无法安全保管或读取时不明文降级、不覆盖既有密钥。具体依赖及平台能力按技术方案实测。
- 秘密不进入 AI 上下文、普通导出、日志或其他功能的默认取数范围。
- 秘密值只在主动查看、编辑、复制或已约定的验证操作中使用明文；后端搜索仅返回所需非秘密展示字段，不返回整本秘密。
- 验证会向记录指定的目标发送必要认证信息；打开浏览器不自动附带秘密。
- 产品目标是保护本地存储和减少误泄漏，不承诺操作系统已被控制时仍绝对安全。
- 未来导出导入需要加密文件和安全的跨设备解密方式，特殊文件格式本身不作为安全保证。

## 12. 主要验收场景

1. 创建两个密码本，记录互不混入；搜索只作用于当前密码本。
2. 同一平台保存多个不同用途的 Key，可按平台、名称、账号或用途找到。
3. 没有当前网络访问能力的内网数据库仍可正常保存、查看、复制。
4. 内置字段不可扩展；自定义类型可建结构并录入多条记录。
5. 秘密默认隐藏，可以直接复制；打开详情不导致全部秘密自动显露。
6. 数据库可以复制单值及明确格式的连接字符串。
7. 复制为新记录允许修改后保存，新记录不携带历史或旧验证结果。
8. 创建后自动验证一次；重新打开密码本不测试；后续按钮可重测。
9. 云凭据、平台账号及自定义类型不发起验证请求。
10. 最小推理验证展示实际检查范围；无法验证不影响记录保存。
11. 修改测试相关字段使旧结果失效；修改备注不影响它。
12. V4 恢复到 V2 时生成 V5，V3、V4 仍能查看和恢复。
13. 历史秘密隐藏，恢复不回放旧验证结果、不改变真实服务密码。
14. 内置平台一键打开管理页面，用户不需要填写或维护该地址。
15. 平台账号有登录地址时可打开，无地址时不显示按钮。
16. 本地存储检查覆盖当前、历史、备注及相关辅助文件的加密边界。
