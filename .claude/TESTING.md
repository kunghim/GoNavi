# 本地测试策略

## 默认原则

测试范围必须与本次修改范围匹配。最高优先级是执行直接覆盖已修改模块、函数或行为的最小测试集；未受本次修改影响的模块不作为日常修复的必跑项。

不要为了“看起来更全面”而默认执行 `go test ./...`。全量测试会遍历整个仓库，包含与当前改动无关的数据库驱动、进程、网络和长时测试，反馈慢且不能提高局部修复的有效验证密度。

## 执行顺序

1. 先执行直接覆盖改动行为的定向测试，例如：

   ```powershell
   go test ./internal/db -run "Test(Chroma|Qdrant)" -count=1
   ```

2. 仅在改动了模块内共享代码，或定向测试不足以覆盖调用方时，再执行该模块的完整测试，例如：

   ```powershell
   go test ./internal/db -count=1
   ```

3. 只有以下情况才执行全量 Go 测试：
   - 修改公共接口、共享基础设施、构建配置或跨多个模块的逻辑；
   - 用户明确要求；
   - 合入前的 CI 或维护流程明确要求。

   ```powershell
   go test ./... -count=1 -timeout=30m
   ```

## 外部服务测试

依赖真实数据库或服务的测试应通过已有环境变量显式启用。未配置服务时保持跳过，不为日常局部修改启动或等待无关的外部依赖。

## 交付说明

报告测试结果时，说明已运行的定向测试和其覆盖范围；若未运行全量测试，明确其未运行原因，不把它表述为失败。
