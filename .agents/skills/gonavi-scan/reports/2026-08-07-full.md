## 产品经理视角发现

### FIND-SYNC-001 差异同步不支持复合主键表

- 类型：产品缺口。
- 严重度：P2。
- 置信度：高。
- 验证状态：已验证（代码与自动化测试）。
- 关联能力：`CAP-SYNC-001`。
- 结论：表到表和 SQL 结果到表的差异同步只支持单列主键；无主键或复合主键会被拒绝或跳过。因此，以复合主键建模的业务表无法使用差异预览与增量同步闭环。
- 证据：`internal/sync/analyze.go:191`、`internal/sync/preview.go:103`、`internal/sync/source_query_sync.go:82`、`internal/sync/sync_engine.go:326`。
- 测试证据：`internal/sync/analyze_i18n_test.go:294`、`preview_i18n_test.go:188`、`source_query_sync_test.go:262` 明确断言复合主键错误路径。
- 影响：使用联合业务键的表只能改用直接导入、调整表结构或通过其他方式同步，无法获得差异对比能力。

验证路径：

1. 准备源表和目标表，均使用两个字段组成复合主键，例如 `PRIMARY KEY (tenant_id, user_id)`。
2. 在数据同步工作台选择差异同步或差异预览。
3. 选择上述源表与目标表并执行分析。
4. 预期结果：系统能够用两个主键字段唯一定位行，生成新增、更新和删除差异。
5. 实际结果：后端返回“复合主键当前暂不支持差异同步/预览”的错误或跳过该表。
6. 自动验证命令：

```powershell
go test ./internal/sync -run "TestAnalyzeUsesCurrentLanguageForReadAndPKMessages|TestPreviewUsesCurrentLanguageForPreflightErrors|TestResolveSinglePKColumnUsesCurrentLanguageForQueryDiffErrors" -count=1
```

本次执行结果：`PASS`，`ok GoNavi-Wails/internal/sync 5.564s`。

建议：将复合主键值建模为有序元组，并统一扩展分页、反查、差异集合和行选择逻辑；验收需覆盖 MySQL-like、PostgreSQL-like 和可选 Driver Agent 路径。
