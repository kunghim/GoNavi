# 给 ZCode 的开发指令

以下正文可直接交给 ZCode。另一台机器先 fetch 个人 Fork 的 `feature/session-assets-handoff`，从本目录读取全部文档；交接工作区与产品实现工作区分开，获取步骤见 README.md 第 7 节。

---

请开发 GoNavi 的“智能体会话资产管理”首版。先完整阅读 `docs/development/session-assets/README.md`，再按它的顺序读取 requirements.md、interaction-design.md、technical-design.md、development-plan.md、acceptance.md、evidence-summary.md。不要依赖你无法访问的聊天历史、可点击原型或本机研究目录。

目标是把会话作为长期资产保全与利用。用户已经确认：新建连接增加“智能体”分类；检测本机安装和可读使用位置后启用 Codex；每种工具一个入口、可有多个历史来源；主页固定智能体分组，点击 Codex 在右侧唯一页签管理。禁用保留配置、节点和资产，关闭页签不停止保护。首版只接 Codex，设计为后续工具留独立适配能力，不实现其他工具的采集或启动。

核心策略不能更改：活动只维护基础信息/按需读源；归档保存最新原始材料及必要依赖；取消归档保留副本并恢复活动原源引用；重归档完整提交再替换，失败保留旧完整副本；原工具删除不清除 GoNavi 资产；GoNavi 单项删除才清理其材料并防止再次扫描自动出现。保存原文、固定 fork 祖先前缀、附件与未知记录，不用摘要代替原始材料。

首版只在 GoNavi 运行期间保护，用文件观察与启动核对，不安装 hook/daemon，不周期备份活动全文。采集、复制、校验、重试及本地解析不调用模型、不向原对话写消息。原工具私有索引默认只读；不要以 resume 全部历史或修改 provider 字段解决索引/兼容问题。

GoNavi 不做新的编码代理。原生继续默认同 provider，跨 provider 使用可读历史新建。优先交给 Codex CLI，自动交接按实际验证能力开放，必须有可用手动材料及说明。用户预览历史引用、当前请求、目标和缺失范围后才交接；不自动执行历史命令、切全局 provider 或复制认证文件。准备材料、入口启动、新 ID 创建与下一轮执行成功分别报告。

开始工作前读取目标工作区实际存在的 AGENTS.md 及其引用资料；本地 `.claude/` 资料存在时按要求读取。缺少个人资料时读取现有 CONTRIBUTING.zh-CN.md、GO_STYLE.md、相关模块代码/测试并遵守交接入口规则，不依赖原机器环境。涉及 Go 先读 GO_STYLE.md，目标文件及测试先读后改。检查 git status、当前任务分支和已有改动。新实现 fetch 最新 upstream/dev，从它建独立 feature/* 产品工作区；已有此任务产品分支则续作。保留交接工作区供读取文档，不直接在交接分支实现，不从个人 dev 或交接分支派生产品分支，不 merge/cherry-pick 文档提交进产品 PR；不覆盖、清理或回退用户改动。

先做 M0：给出集成文件范围、模型与接口建议、只读格式适配、观察/原子提交/锁方案、拟支持平台矩阵和 CLI/手动交接方案。然后按 development-plan.md 实现 M1–M6，持续完成所有适用 P0。先走通保全闭环，再完成阅读/导出/删除与复用。一个阶段完成不等于整个功能完成。

现有 Wails v2、Go、React 18、Ant Design、Zustand、i18n、QueryResult 分层保持；不要引入 Electron、新状态/UI 库或扩大 db.Database。独立 sessionassets 领域包及 UI 目录，接线保持薄；超标文件不得净增业务逻辑；生成绑定由 Wails 生成，禁止手改。六种语言资源同步，数据库与现有内置 AI 功能不得回归。

用虚构夹具、隔离历史目录及可控故障验证，不读取其他私人会话、复制凭据或制造收费测试轮。真实原工具或模型测试只有在用户明确指定可丢弃样本、目标和认证条件后开展；没有条件就标未执行并继续独立工作。任何假服务成功都不能写成真实窗口创建/模型召回通过。

每完成一个阶段在产品工作区的已验证忽略目录更新本地进度，报告已完成、实际验证、限制与下一步。普通模块、字段、依赖和布局细化按专业判断直接处理；只有需要常驻服务、活跃全文自动备份、云/远程采集、新凭据系统、内置代理运行界面或改变已确认保全策略时向用户说明重大变化，不要反复确认既定方案。

最终按 acceptance.md 填写 V-01–V-33 的适用结果及平台能力矩阵，包含失败/未执行项；提供真实 GoNavi 用户测试入口和本地实现摘要。按风险跑相关 Go/Vitest、前端构建和共享接口回归；完整 Wails 构建/最终运行按本地规则交给用户。构建通过不替代产品验收，真实模型条件不足不允许伪造通过。

对 ZCode 的实施授权仅为本地实现和验证。用户对交接包的 commit/push 授权不扩展到产品代码；不要自动 commit、push、创建 PR、远程评论或安装系统服务。`.claude/`、AGENTS.md、研究资料、设计原型与本交接文档不进入产品 PR。若用户后续授权提交，仍先审查代码/测试/必要多语言与配置范围，并遵循仓库用户人工测试及 PR 流程。
