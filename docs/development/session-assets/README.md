# GoNavi 智能体会话资产：开发交接入口

- 交接版本：v1.1（跨设备同步版），2026-10-06。
- 状态：用户已同意首版边界，并将安排 ZCode 开发；当前没有产品代码实现。
- 位置：`docs/development/session-assets/`，通过个人 Fork 的 `feature/session-assets-handoff` 分支同步。用户已明确授权本次交接文档提交与推送；本包属于开发资料，不进入产品实现分支或上游 PR。

## 1. 开发目标

让会话成为可长期管理的资产：用户启用本机 Codex 后，GoNavi 发现会话、归档时保存最新原始材料；即使原工具删除归档，已保存材料仍可查找、阅读、导出并用于原工具的新会话。原会话还在时尽可能通过受支持入口继续原 ID。

智能体与数据库连接同级接入；GoNavi 管理资产与交接，执行和对话继续留在原工具。不要另做一个 Codex。

## 3. 首版冻结决策

| 编号 | 必须遵守的决定 |
| --- | --- |
| S-01 | 首版仅接入本机 Codex；架构按能力支持后续 Claude Code、ZCode、WorkBuddy，不显示未实现工具为可用 |
| S-02 | 保留全局“新建连接”；分类增加“智能体”；选中 Codex 后是检测/启用页，不是数据库表单 |
| S-03 | 主页固定“智能体”系统分组；每种工具一个节点，右侧唯一管理页签，不将每条聊天放入左树 |
| S-04 | 当前本地 GoNavi 数据根内同种工具只接入一次；历史位置可多个，provider、项目、CLI/IDE 不产生重复工具节点 |
| S-05 | 首次启用要求安装及可读使用位置检测通过；可手动定位重检，不要求已有一条聊天或模型认证成功 |
| S-06 | 关闭页签不禁用；禁用/卸载保留配置、节点、索引与备份；已保存资产可离线查看、导出和复用 |
| S-07 | 活跃只维护基础元数据，正文按需读取，不默认持续复制或做全文持久索引 |
| S-08 | 归档立即安排原始材料保全，语义处理延后；首次启用补保存已有归档 |
| S-09 | 取消归档指回原工具活动源，旧备份保留；再次归档完整提交后替换 latest，再清理旧副本 |
| S-10 | 原工具删除不删除 GoNavi 资产；GoNavi 单项删除才清理本资产材料，并防止扫描自动重新纳入 |
| S-11 | 原源引用与独立备份引用分开；原记录状态、备份状态、可读完整性、交接结果分维度表达 |
| S-12 | 材料自包含，保存原文、固定 fork 祖先前缀、必要附件和未知记录；首版不做跨资产物理去重 |
| S-13 | 首版只在 GoNavi 运行期间保护，以文件观察与启动核对为主；不自动安装 hook/常驻服务 |
| S-14 | 元数据更新、复制、校验、重试、解析均不调用模型，不把状态写入原会话上下文 |
| S-15 | 同 provider 尽力原生继续；跨 provider 携带可读历史新建，不改写原记录，不改正在使用的全局 provider |
| S-16 | 原工具交接优先 Codex CLI；自动窗口/会话交接按验证能力启用，手动材料与说明为必需兜底 |
| S-17 | 用户选择范围与目标后预览，历史引用与当前请求分开；不重跑历史工具调用、不自动继承旧权限 |
| S-18 | 首版不做默认模型摘要、云同步、远程持续采集、回收站、批量永久删除、按日期自动清理、标签/收藏、资产包导入 |
| S-19 | 默认材料库随 GoNavi 数据根；启用时可选择本地材料库位置；启用后位置只读，首版不做库迁移 |
| S-20 | 本地原始材料不新增静态加密功能或已加密承诺；平台权限保护及已有 secretstore 仍适用，认证不进入备份 |

S-13 与 S-16 已在最后一轮讨论获用户同意。仅运行期间保护意味着停机期间归档又删除的、从未保存过的材料可能无法补回；这是产品边界，不能用静默备份活跃全文补偿。

## 4. 首版完成标准

必须完成全部 P0 与 [验收](acceptance.md) 中适用的必需项。开发任务按阶段推进，但“启用 → 找到 → 归档保全 → 原删除后读取导出”只是首个检查点，不是全部任务完成。

自动创建及原生打开属于能力分级：必须完成用户可用的手动交接，自动路径若未验证须明确不可用并保留材料；不得用演示成功、进程启动或 resume 被接受作为真实下一轮成功证据。若既无法交接原工具、也不能提供有效手动材料，不能验收复用功能。

发布支持的平台与入口逐项记录产品实测；未测标未测，不能把历史实验列为产品通过。真实模型召回测试受用户指定的可丢弃样本、目标和凭据条件限制；无条件时保留为未执行，不阻塞虚构夹具开发，也不伪造通过。

## 5. 开发前仓库约束

读取目标 clone 实际存在的 AGENTS.md 与其引用的仓库指令；本地 `.claude/` 上下文、流程及环境资料存在时按要求读取。若另一台机器或干净上游分支没有这些个人资料，读取现有 CONTRIBUTING.zh-CN.md、GO_STYLE.md 和相关模块代码/测试，按本文的基线与交付规则推进，不要求复制原机器环境。Go 修改前读 GO_STYLE.md。以实际文件为准，不把本交接时的路径或函数名当作不会变化的接口。

产品实现是新任务：开始前检查工作区与已有任务，fetch 最新 `upstream/dev`，从它创建独立 `feature/*` 分支/工作区。不要直接在本交接分支写产品代码，不从本地 dev 或本交接分支派生产品分支，也不要 merge/cherry-pick 交接提交进产品 PR。已有该任务产品分支时续作，不重复创建。保留用户已有改动。

现有 Wails/React/Ant Design/Zustand/i18n 与 QueryResult 契约保持。超标文件不净增新业务逻辑；新模块拆分，生成绑定用 Wails 生成。本次授权仅覆盖交接文档提交与推送，不授权后续产品代码提交、推送、PR、远程评论或系统服务安装。后续按用户另行指令执行。

## 6. 交接可携带性与原型

ZCode 不需要读取本会话完整历史。另一台机器 fetch 本交接分支即可取得全部 8 份 Markdown；实现时保留交接工作区供查阅，在基于最新上游的独立产品工作区中开发。重新检查目标机器的仓库指令与环境，不把本包带入产品 PR。

本机研究原始目录是可选证据，缺失时看 [证据摘要](evidence-summary.md) 并建立虚构夹具；不要为补齐证据遍历私人聊天或复制认证文件。

两份可点击原型仅为视觉参考：接入预览 v0.2 展示启用、节点、禁用和复用；详情预览 v0.1 展示材料来源及交接。文档已修正其不完整之处（完整筛选、真实能力判定、备份事务等），开发不依赖这些 HTML；不把原型样式或假数据直接写入产品。

在个人 Fork clone 中先检查工作区，再获取交接分支；以下 switch 适用于本机尚无同名分支的情况，已有时使用 `git switch feature/session-assets-handoff`：

```bash
git fetch origin --prune
git switch --track origin/feature/session-assets-handoff
```

先让 ZCode 阅读 [开发指令](zcode-instructions.md)。该分支只承担跨设备文档交接，保留为查阅工作区。新实现可在另一个工作区创建，示例名称未使用时执行：

```bash
git fetch upstream --prune
git worktree add -b feature/session-assets ../GoNavi-session-assets upstream/dev
```

上例目标目录和分支名须先检查是否已存在；已有本任务产品工作区则继续它。ZCode 从交接工作区读取本文及相邻文件，在产品工作区修改代码。实现进度记录放产品工作区的本地忽略目录，并验证其忽略状态，不把交接分支或个人辅助提交合入产品分支。不要为获取本包而替换用户的 origin/upstream 配置。
