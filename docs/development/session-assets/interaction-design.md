# GoNavi 会话资产交互设计

- 版本：v0.3，开发交接基线，2026-10-06。
- 依据：[需求文档](requirements.md)及已有本机验证。
- 状态：入口及首版边界已确认，作为 ZCode 开发输入；产品尚未实现。接入预览为 v0.2，旧会话详情预览为 v0.1，二者均为虚构交互示例。文档基线见 [交接入口](README.md)。
- 本轮由产品设计主动决策；下面的默认方案不改变“归档保存最新材料、活跃以原始来源为主”的已确认策略。

## 1. 设计结论

智能体与数据库连接在 GoNavi 的资产接入体系中处于同一级别。“新建连接”的分类增加“智能体”，用户选择 Codex 等工具后启用本机资产管理。主页左侧出现固定“智能体”分组，每种工具一个节点，点击后在右侧工作区管理该工具的会话资产。

右侧继续采用会话列表与详情；用户先找到资产，再查看材料，最后决定如何继续利用。GoNavi 不在该工作台中提供模型聊天输入框或编码代理运行窗口。界面入口统一，领域实现仍按智能体与数据库各自能力划分。

默认不是归档列表：全部资产包含活跃、归档、源已删除和来源暂不可用的记录。原工具的状态只是一项筛选条件，避免用户以为归档是 GoNavi 中唯一需要保存的资产。

交互的辨识点是详情顶部的“当前材料来源”：明确正在读取原工具还是哪次 GoNavi 备份。它决定用户能否看到最新内容，比单独一个“已同步”图标更有用。

## 2. 本轮产品决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D-01 | 智能体与数据库连接同级接入；新建连接增加智能体分类，主页固定分组 | 用户明确提出，沿用现有资产接入与左侧树心智 |
| D-02 | 主页左树选择工具，右侧页签展示会话列表 + 详情；窄窗口详情可返回列表 | 工具级导航使用现有左树，避免增加重复的一级导航 |
| D-03 | 默认全部会话，按最近会话更新时间排序 | 用户记得工作的时间，而不是备份处理的时间；后台保存不应扰动列表顺序 |
| D-04 | 原记录与备份分两列；错误只在需要用户处理时强调 | “源已删除 + 备份可用”是正常可用状态，不应呈现为红色失败 |
| D-05 | 原源可用时突出“继续原会话”；源明确删除时突出“携带历史新建” | 让主动作与当前真实能力相符，保留另一条可用路径 |
| D-06 | 跨 provider 首版默认携带历史新建，不提供默认改写历史或跨 provider 原生续聊 | 已验证存在追加历史后无法回切的情况，优先保护原记录 |
| D-07 | 新建流程是一个两阶段面板：选材料与目标 → 预览并交给原工具 | 在对外传递前明确范围与去向，避免大量参数分散在多个弹窗 |
| D-08 | 默认选择最近一次完整讨论，允许选轮次；“全部可读历史”是显式选项 | 长历史不能默认无界发送；不能以自动摘要替代原材料 |
| D-09 | 未完成整理时按需本地提取；首版不默认调用模型生成摘要 | 避免额外费用、隐私传递和改变用户原任务的内容 |
| D-10 | 首版没有批量永久删除和自动按时间清理 | 减少重复原工具“清空归档后才发现需要”的误操作模式 |
| D-11 | 删除单条资产有明确范围确认；子资产必需材料保留归子资产使用 | 清理一个资产不能静默损坏另一个仍保留的资产 |
| D-12 | 首版不增加收藏、标签体系或全文搜索索引；支持基础筛选及当前正文内查找 | 先完成发现、保全、复用闭环；正文按需读取不改变活跃采集策略 |
| D-13 | 首版按 GoNavi 实际运行期间显示监听状态，不默认安装系统常驻服务 | 常驻组件会改变部署、安全和退出行为，技术方案需要独立评估 |
| D-14 | 每个本地 GoNavi 使用环境内，每种智能体仅一个管理入口；来源目录和入口可多个 | provider、项目、CLI/IDE 不应生成重复智能体连接 |
| D-15 | 初次启用要求识别安装及可读的使用数据位置；支持手动定位后重新检测 | PATH 缺失不等于未安装；不能仅凭一个同名文件夹判定可接入 |
| D-16 | 禁用停止采集，保留节点、设置和资产；卸载不自动移除资产 | 长期保存价值不依赖原工具仍安装，避免重复误删场景 |

D-06、D-10、D-12 是首版优先级决策，后续扩展不自动进入本次交付。运行期间保护及 CLI 优先、手动材料兜底已经用户同意；跨 provider 原生尝试、常驻服务或更广的数据采集需另行说明范围变化。

## 3. 信息架构与入口

### 3.1 新建连接中的智能体分类

保留全局“新建连接”入口及现有数据库分类，在分类列表增加“智能体”。“全部”及名称搜索也可以找到已支持的智能体，卡片明确标出类型。选中后进入专门的启用页，不出现主机端口、数据库账号、测试 SQL 等字段。

首版只展示已实现接入的 Codex；Claude Code、ZCode、WorkBuddy 是后续同一分类下的扩展，不能以可点击卡片暗示已经支持。已支持但本机未安装的工具仍显示，并解释不能启用的原因。

| 检测状态 | 选择页动作 |
| --- | --- |
| 已安装，识别到可读历史/已初始化使用目录，未启用 | 启用 |
| 已安装，但未发现可识别的使用数据位置 | 先在原工具初始化使用，或指定位置重新检测 |
| 未检测到安装 | 查看条件、指定安装位置、重新检测；不能直接启用 |
| 已安装，但目录无权限或格式不受支持 | 展示具体原因，修正位置/权限后重新检测 |
| 已启用 | 打开管理，不重复创建 |
| 曾启用，目前已禁用 | 重新启用，沿用原入口与资产；检测仍须通过 |

“安装且使用”以已识别的安装入口和数据位置为证据，不要求一定已有一条聊天。只有桌面或 IDE 安装、没有独立 CLI 时也可以启用其受支持的历史采集能力；能否启动会话另外检测。检测不发送测试消息，也不要求 API Key 或模型连接成功。只见备份或历史残留但没有安装，不创建新的实时接入；已有资产的离线访问不受此限制。

启用页显示：工具身份、检测结果、可用历史位置、GoNavi 保存位置及保存范围。主按钮为“启用 Codex”；确认后建立索引、核对已有归档，并开始运行期间监听。不得在确认纳入前自动扫描聊天正文或建立备份。

### 3.2 主页左侧固定分组

“智能体”是与现有连接列表并列的系统分组，不是可以任意改名、删除或混入数据库连接的用户分组。数据库既有分组结构不改。

```text
现有数据库连接与用户分组
智能体
  Codex
  Claude Code       ← 后续接入后才出现
```

首次成功启用后显示此分组。节点使用工具名称，不创建“Codex 官方”“Codex 华龙”或每个项目一个 Codex 节点。首版唯一范围是当前本地 GoNavi 使用环境，不是跨设备全局唯一；远程主机的组织留到后续设计。

单击工具节点在右侧打开或激活已有的该工具管理页签；重复点击不产生重复页签。不把每条会话放进主页左树，也不再嵌套一套工具选择导航。关闭管理页签不会禁用监听。

节点显示启用、已禁用或来源异常状态。右键提供打开管理、重新检测、设置、禁用/重新启用；不把“删除连接”作为默认动作。禁用后节点仍在，可打开已有资产，页面明确不再自动采集。卸载、数据位置失效或短暂不可达只改变可用状态，不自动删除节点、索引或材料。

点击“智能体”分组标题只控制展开折叠，首版不增加跨工具总览页面；以后跨工具复用仍从源工具的资产详情选择目标工具。

### 3.3 右侧工具管理页

页签名称为“Codex”，页面标题“Codex · 会话资产”。工具级入口内可接入多个历史位置；CLI、桌面和 IDE 发现相同历史时合并识别，独立位置作为来源筛选，provider 作为历史信息和筛选条件。它们都不计作第二个工具连接。

管理页内筛选：

- 全部会话：所有已经纳入的资产。
- 有备份：至少有一份可用的已提交副本；旧副本可用也在这里，状态必须说明覆盖时间。
- 需关注：没有可用材料、更新失败、依赖不完整等影响保全或复用的情况。
- 来源：按已纳入历史目录筛选，不要求用户先理解桌面、CLI 与 IDE 的底层目录关系。

不做“归档”和“备份”两个互相排斥的顶层集合。一条资产可以同时是活跃源、有旧备份、待更新。

“管理来源”位于工具管理页的工具栏，用来维护同一工具下的历史位置；启用/禁用则管理整个工具。二者不是重复创建连接。

## 4. 会话列表

### 4.1 默认显示

主信息为会话标题；辅助显示项目或工作目录、来源工具和历史 provider。桌面宽列表提供最近更新时间、原记录状态和备份状态；展开详情后列表保留最重要的三列：会话、原记录、备份。

默认选中最近查看的资产；首次打开可以没有选中项。搜索或筛选导致当前项不可见时，不偷偷改到另一个资产，详情提示当前项不在筛选结果中或由用户主动选择。

搜索框文案：“搜索标题、项目或 provider”。范围为基础元数据，不误称“搜索所有聊天内容”。当前详情中的正文查找单独按需提供。

### 4.2 状态文案

| 维度 | 推荐文案 |
| --- | --- |
| 源仍在 | 活跃 / 已归档 |
| 确认物理删除 | 原记录已删除 |
| 暂不能读取 | 来源不可用 / 原记录状态未知 |
| 只有基础索引 | 未备份 |
| 有有效副本 | 备份可用 · 日期时间 |
| 更新失败但旧副本有效 | 更新失败 · 旧备份可用 |
| 尚未完成保存或校验 | 正在保存 / 待校验 |
| 子材料不足 | 材料不完整 |

“活跃 / 未备份”符合默认策略，不当作失败。没有归档但 IDE 列表已移除时，资产仍按原始来源呈现；入口可见性只有可靠证据时才显示。

不默认展开完整 ID、JSONL、SQLite 表名、hash 或内部 provider 配置。这些进入详情“技术信息”，需要排障时再查看。

## 5. 会话详情

### 5.1 顶部：身份、读源与动作

- 标题，工具、历史 provider、项目/工作目录、会话更新时间。
- 读源带：例如“正在读取 GoNavi 备份 · 10/05 18:24”，另行说明“原记录已删除”。
- 原始路径仍可读时默认读取原源；源不可用时读取有效副本并显示具体覆盖时间。
- 活跃源与旧副本并存时，可在“材料”中显式查看旧副本，但不因此改变原工具路径。
- 再次归档后 latest 成功更新，刷新读源带；失败保留旧副本及失败说明。

| 情况 | 主动作 | 其他动作 |
| --- | --- | --- |
| 源可用，同 provider 原生入口受支持 | 继续原会话 | 携带历史新建、导出材料 |
| 源明确删除，有完整备份 | 携带历史新建 | 导出材料；原生继续不可用并解释原因 |
| 来源不可达，有旧备份 | 携带历史新建 | 重新检查来源、导出；标明副本覆盖范围 |
| 材料不完整但部分可读 | 查看可用材料，选择携带历史新建 | 先列出缺失项，禁止标为完整 |
| 没有可用正文或副本 | 重新检查来源 | 展示最后元数据，不制造空白“已恢复”聊天 |

动作词“继续原会话”始终意味着尽量沿用原 ID；“携带历史新建”意味着新 ID。按钮不可用时理由应可见，不仅放在悬浮提示里。

### 5.2 历史页

以消息和轮次阅读，而不是直接显示原 JSONL。用户/助手消息为主，历史工具调用和结果默认折叠，可展开阅读。系统、环境和原项目指令单独分类，不以用户发言的样式混排。

图片区分可查看的内嵌/外部内容与缺失引用；未知项保留访问原始材料的入口。长历史按需加载，在历史页内可定位消息和查找正文。不靠无界渲染整条大型记录实现查看。

fork 详情显示“来自某会话的分支”及分叉时历史说明；不默认展示复杂关系图。缺少祖先材料时直接在消息对应范围标明缺失。

### 5.3 材料页

显示当前可利用的材料：原始记录、最新副本、分叉时祖先历史、附件和派生可读材料。每项说明可用、缺失、部分可用或尚未整理。

材料页是查看完整性、解释覆盖时间的入口，不是多版本管理页面。“导出原始材料”与“导出可读历史”分开，后者复用用户选择的范围。

复制或导出原文可能包含会话本身的敏感内容，实际操作前呈现材料范围；不把日常查看改成反复确认流程。

## 6. 携带历史新建：核心流程

### 阶段一：选择材料和目标

1. 从当前资产进入，保留标题和材料来源。
2. 默认选择最近一次完整讨论，展示涉及的轮次；可切换“选择轮次”或“全部可读历史”。若不足以识别完整讨论，明确使用“最近可读轮次”，不宣称已理解任务边界。
3. 目标工具首版固定 Codex；入口按实际可用能力显示，默认受支持的 Codex CLI。不能自动创建 IDE/桌面窗口时仍提供手动交接。
4. provider 选择原工具已配置且可用的目标；历史 provider 可用时优先预选。当前全局配置和历史配置不一致时不静默覆盖。该流程不承担建立新的凭据管理体系。
5. 默认原工作目录，目录失效时要求选择一个可用目录或明确无项目运行。旧路径不自动变成目标工具的可访问文件。
6. “接下来要做什么”为当前新任务，可选；填写后随选定历史一起交给原工具。未填写则只交接资料，不能猜测要执行的工作。

### 阶段二：预览与交接

预览分成“历史引用”和“当前请求”，列出历史消息、工具结果、附件的包含范围，说明被省略、缺失或不透明的内容。旧系统/项目指令默认不提升为新指令，历史工具调用默认不重新执行。工具调用与结果需要成组选择；大段工具输出默认不全部带入，可显式选择相应可读材料。

文字量与目标可用预算可以可靠估计时才展示数值。首版不显示看似精确但未验证的 token 数。超出已知限制时要求缩小范围或选择支持的手动材料导出，不静默截断、不自动收费摘要。

提交按钮按真实动作命名：可自动创建则“交给 Codex 新建”；只能准备文件则“导出交接材料”；只能复制则“复制上下文”。不把三种结果都写成“创建成功”。

返回结果区：

- 自动路径：工具/入口、provider、工作目录、新 ID 或官方入口、实际创建状态。没有执行证据时不显示“历史已全部恢复”。
- 手动路径：材料位置或已复制状态、经过核验的启动操作说明。清楚说明还没有新建会话。
- 失败：保留当前选择与预览，提供重试、切换可用入口或导出；不自动改成另一个 provider 发送。

本预览不会真正启动模型或发送资料；成功态应明确标为演示。

## 7. 继续原会话

采用当前来源支持的官方方式，在同 provider 下打开或准备原生继续使用。保持原生 ID、工作目录和原工具自己的权限控制；GoNavi 不在此处复刻原工具的执行审批。

若目标入口只能通过 CLI 继续，而无法恢复 IDE 的外层列表，按钮或结果必须说明“在 Codex CLI 继续”，不能写“已恢复到 PyCharm”。

仅准备启动命令不算已打开；仅 resume 接口被接受不算下一轮执行成功。失败后保留原材料，提供显式“改为携带历史新建”，不自动添加模型测试轮。

首版关闭跨 provider 原生继续作为默认路径；provider 改变时导向新建流程。此决策是保护原历史，不取消同 provider 下的尽力原生续聊能力。

## 8. 来源设置与保存状态

首次接入通过“新建连接 → 智能体 → Codex → 启用”，识别默认本地历史位置，并允许用户指定其他实际位置。已接入后通过“管理来源”补充或修正位置。用户确认纳入后建立基础索引、补保存已有归档；不自动复制活跃会话。

来源设置显示名称、历史目录、监听是否运行、最近核对时间、发现数量、保存状态和失败项。当前只有 Codex 时不加工具下拉；预留后续接入结构，不将未来工具作为可操作项展示。

禁用智能体停止其全部来源的后续采集；关闭其中一个来源只停止该来源。已有设置与资产均保留；“删除资产”是独立动作。重新启用使用原有入口并补核对，不创建第二个同类节点。启用时可选择材料位置；首版已启用后的保存位置只读，不提供目录迁移，避免直接改指针使旧资产失联。管理来源仍可新增、停用和重新定位；重定位不能直接覆盖冲突身份。

工作台底部常驻简短状态：“运行期间监听 · 最近检查时间”。退出 GoNavi 后停止监听时按真实保护范围说明，不能让“已启用”暗示常驻保护。首版不逐条弹出归档成功通知。

更新失败在对应资产和“需关注”聚合；旧材料有效时说明旧备份时间。确实没有可用副本或需要用户处理权限、磁盘时给出一次可定位的通知。重新检查和重试不自动向原聊天写消息。

## 9. 删除、空态与异常

删除入口放在详情更多操作，首版不放在列表每行的主操作区，不提供一键清空归档或自动按日期删除。

确认界面明确“删除 GoNavi 资产”：列明将清理的独立副本、索引和派生材料，说明原工具会话不受影响。存在子资产引用时，说明必要历史仍属于保留的子资产；不能把这部分保留伪装成完全擦除。最终文案与底层删除语义须在技术方案中一致验证。

首版采用直接删除加确认，不引入完整回收站。界面不得承诺 GoNavi 删除后仍可恢复；重新纳入尚存在的源是新的主动操作，与备份恢复不同。

| 情况 | 展示与下一步 |
| --- | --- |
| 尚未启用智能体 | 新建连接中的智能体分类，检测并启用 |
| 已接入但没有可用来源 | 管理来源，解释索引、归档保存的范围 |
| 智能体已禁用 | 可查看已有资产，停止采集；重新启用须检测通过 |
| 原工具已卸载但仍有备份 | 保留资产访问，可阅读导出或交给其他可用目标；不能原生继续 |
| 没有匹配资产 | 显示当前搜索/筛选条件，允许清除，不宣称历史被删除 |
| 初次归档保存尚未完成 | 显示保存中，继续提供可读取的原源；完成后更新材料状态 |
| 副本更新失败 | 显示旧覆盖时间和具体原因，源仍可用时可重试 |
| 来源不可达且没有副本 | 展示最后基础信息，检查目录/来源；不能允许“携带历史新建”空提交 |
| 依赖或附件缺失 | 列出缺失范围，可选部分可读材料，提交前再次显示遗漏 |
| 目标工具未安装/入口不可用 | 提供安装条件、其他已验证入口或导出；不偷偷下载安装软件 |
| 目标认证无效 | 交给原工具完成认证；保留预览，不复制完整认证文件到资产备份 |

## 10. 视觉、键盘与预览范围

沿用 GoNavi V2 的绿色主动作、中性背景和紧凑工具栏。标题以内容为主，不增加 KPI 卡片、彩色资产卡片或营销式说明。状态同时使用文字，不能只靠颜色判断。

所有列表项、筛选、页签和按钮可通过键盘操作；面板关闭返回触发按钮，Esc 关闭暂未提交的面板。正文读取过程、保存进度和失败均有可识别状态，不影响用户在原工具中使用。

v0.1 可点击预览覆盖：元数据搜索与 provider 筛选、三种资产视图、会话切换、原始/副本读源说明、历史与材料、两阶段新建、原生交接、删除确认及来源查看。v0.2 独立接入预览覆盖智能体分类、模拟检测与启用、主页固定分组、页签关闭、禁用与重新启用，以及禁用后的备份阅读与交接预览。两份预览均使用虚构数据，不连接本机历史或 provider，不产生真实删除、备份、安装或模型请求。

批量动作、全文索引、常驻服务、备份加密和跨设备导入不在预览中提前实现。后续技术方案首先应满足上述界面所承诺的状态和行为，而不是让产品显示内部协议名。

## 11. 下一步技术方案输入

产品侧已确定的工程边界：

- 独立资产索引，不改变原工具历史数据库；原路径与材料集合分别管理。
- 复用连接选择与左树入口，但智能体启用配置、检测和会话资产不强行实现 SQL/数据库驱动接口；工具级单实例，来源级多实例。
- 同 provider 原生继续与新建交接为独立能力；新建目标配置不通过修改全局配置实现。
- 归档触发保存，启动补核对；保全状态与解析/模型执行状态分别记录。
- 材料集合须完整提交，fork 依赖可去重，但逻辑上归属于引用它的资产。
- 启动/交接依入口能力降级，不能为了统一按钮假装所有入口都能自动创建窗口。
- 首版限定运行期间保护；若工程评估发现必须安装常驻组件，作为较大变化向用户确认。

见 [技术方案](technical-design.md)：模块划分、存储边界、监听与补核对、材料提交事务、Codex 调用与配置隔离，以及首版平台能力矩阵。实际开发顺序与完成标准见 [开发任务](development-plan.md) 和 [验收清单](acceptance.md)。
