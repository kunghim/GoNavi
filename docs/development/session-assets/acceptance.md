# 首版验收与测试要求

- 版本：v1.0，2026-10-06；全部状态初始为未执行，不能把设计稿或旧实验填为产品通过。
- 依据：[冻结范围](README.md)、[需求 FR/AC](requirements.md)、[开发阶段](development-plan.md)。

## 1. 验收方法

单元/领域测试使用临时目录、虚构 JSONL/SQLite 和可控故障；UI 用后端隔离数据及真实 GoNavi 页面。安装检测通过可注入的路径/命令探测验证逻辑，再在实际平台核对受支持安装入口。不要用生产密钥或真实业务历史充当自动化夹具。

受控真实 Codex 集成测试只操作明确标记可丢弃的测试会话及隔离配置，不触碰当前正在使用的研究/业务聊天。模型测试必须有用户指定的目标及合法认证条件；没有条件标未执行，继续本地测试，不借用或导出私人凭据。不得为测试全局切换当前 provider 或安装 hook/daemon。

文件缺失模拟用于检验副本独立性，不能声称它证明真实原工具 delete 接口行为。协议 create/resume 的模拟用于应用状态判断，不能声称它证明真实模型召回或窗口打开。

## 2. 用例清单

| 编号 | 输入/操作 | 必须观察的结果 |
| --- | --- | --- |
| V-01 | 同一个工具并发启用、重复启用；同目录以别名再次加入 | 只有一个工具入口/观察器；来源身份去重，冲突材料不被无条件合并 |
| V-02 | 未安装、PATH 缺失但指定安装可用、未初始化、无权限、未知版本、IDE-only | 原因分开；可重检；位置改变使旧检测失效；能读历史与能启动会话独立；检测不发送模型轮 |
| V-03 | 新建连接分类、全部/名称搜索、点击已启用 Codex、重复点击树节点 | 专门启用页；固定系统分组；一个节点、一个工具页签；未实现工具不假装可用 |
| V-04 | 关闭页签、禁用、退出重开、重新启用；卸载原工具后有副本 | 关闭不禁用；禁用保留节点和资产；恢复原入口；卸载后能看已保存材料；观察状态真实 |
| V-05 | 启用但观察注册失败/锁占用；GoNavi 停机期间隔离源归档又移除 | 显示未保护/具体原因；不承诺常驻；未捕获且已消失内容不可补回；旧副本仍可用 |
| V-06 | 活动/归档、项目内外、CLI/IDE 同历史、多个历史位置与 provider | 都能发现；当前 provider 不隐藏旧资产；同真实源去重，不只凭 ID 合并不同来源 |
| V-07 | 标题/目录/provider 搜索，时间与源/副本筛选，按源更新时间排序 | 元数据查询正确，备份更新时间不扰动源排序；筛选不偷偷切换详情，不称全文搜索 |
| V-08 | 首次启用时有归档；运行时新归档；重复目录事件 | 尽快自动复制最新原文和必要依赖；元数据与复制异步可观察；重复事件不生成多份永久备份 |
| V-09 | 取消归档→续聊→再次归档；重归档失败 | 原源指回活动位置；旧副本保留；新完整 latest 成功替换后旧材料才回收；失败旧副本有效 |
| V-10 | 隔离源归档后立即移除；无旧副本及有旧副本各一次 | 尽力捕获，失败不伪造成功；旧副本保持；报告捕获率/结果，不宣称全部竞态被消除 |
| V-11 | ENOSPC、半写进程终止、完整候选未提交终止、已提交未清理终止、候选损坏 | 每个切点重启校验；旧完整材料不损坏；完整合法候选可恢复，不完整/损坏不能提交；清理不损害唯一有效材料 |
| V-12 | 事件遗漏/观察重连/应用重启；源仍在与源已不在 | 核对现存归档和未完成候选，能补的补；最新副本状态可由清单修复；不能补的如实报告 |
| V-13 | 同库两个写入实例；current 与索引不同步；未知库版本 | 单写入者或明确只读/占用；无并行破坏；恢复以有效提交清单为材料依据；未知版本不覆盖 |
| V-14 | 旧保存任务与重归档、禁用、删除同时发生 | 老任务不能覆盖新版本或复活被删除资产；取消/安全结束有确定结果；无泄漏队列或错误成功 |
| V-15 | 根→子→孙，父在分叉后追加不同内容，随后移除整个原链 | 子材料包含必要固定祖先前缀；不混入分叉后新内容；副本独立可读；缺祖先时不标完整 |
| V-16 | 内嵌图片、存在/缺失外部附件、仅引用文件、无法解释附件项 | 对应字节/引用/缺失情况明确；原记录不被改动；不递归复制项目；导出保留可用附件和清单 |
| V-17 | 未知字段/记录、明文与不透明压缩、工具调用及结果 | 原文保留；工具成对关联并作为历史展示；密文不伪解码；解析失败不显示为空会话 |
| V-18 | 活跃持续追加、索引/复制/重试/本地解析全部执行 | 没有默认活动全文副本/索引，没有模型请求或原聊天消息，无备份工具调用；原认证/配置和私有数据库无写入 |
| V-19 | 完全移除隔离源的 raw/索引/依赖，只保留 GoNavi 库；禁用工具 | 列表、阅读和导出不依赖原文件残留；读源和覆盖时间正确；可选择新会话材料 |
| V-20 | GoNavi 删除单项、清理失败、重新扫描及应用重启 | 确认范围；抑制身份持久化；源原记录不被删除；清理失败可见；同源不会自动重新出现 |
| V-21 | GoNavi 删除父资产，子/孙资产仍保留 | 子/孙自包含材料仍有效；父资料必要片段属于子保留范围，删除文案没有承诺一切相关内容擦除 |
| V-22 | 历史目录移动、挂载缺失、权限变化、目标工作目录失效 | 暂不可达不误报永久删除；副本可用；重新定位不覆盖冲突身份；交接可改目录，材料不等于项目文件 |
| V-23 | 小样本和大型合成 JSONL（建议不少于 512 MiB），正文分页和查找 | 不全量读入/渲染；内存、耗时和取消响应有记录；已保存的范围与未知项准确，没有静默截断 |
| V-24 | 原始集合导出和选定可读资料导出，源已不存在 | 导出独立可读、校验正确、来源与范围明确；不含 auth/完整 provider 凭据；不是假的文件成功提示 |
| V-25 | 可用同 provider 原会话；resume 受理但实际下一轮报错；不支持原生入口 | 成功阶段分开，保持原 ID；报错保留资料，显式提供新建/导出；不假装恢复 IDE/桌面列表 |
| V-26 | 华龙→官方的虚构历史选取、预览、手动材料；自动入口受支持时实际交接 | 历史引用与当前请求分开；目标、目录、覆盖与省略可见；有效手动材料必需；自动成功须有证据 |
| V-27 | 历史 DeepSeek 配置、当前 GPT 目标、错误继承环境、多个已有 provider | 目标依据本次实际配置；不被旧预设错误覆盖；其他运行会话的全局 provider/认证不改变，查询不隐藏历史 |
| V-28 | 没选材料、已知超预算、预算未知、工具对只选一半、旧权限/系统指令 | 提示无材料；超限要求缩小或导出；未知预算不造精确数字；工具对一致；旧指令不提升为新授权 |
| V-29 | 仅导出、仅启动进程、拿到新 ID、模型轮完成、取消或失败 | 状态/按钮准确；不能把准备材料显示为会话创建/执行成功；失败保留选择且不改换 provider 偷发 |
| V-30 | 六语言、键盘/焦点、窄窗口与桌面窗口、原数据库及原 AI 功能 | 文案走 i18n；操作可达；主树/页签/SQL 上下文不回归；无超标文件净增业务或手改绑定 |
| V-31 | 错误/诊断/日志、Wails 返回、原始材料与交接位置检查 | 不泄露凭据/正文到日志或前端元信息；目录/文件按平台用户权限；原始材料不含认证备份；不宣称静态加密 |
| V-32 | 各实际发布平台及已声明 Codex 入口/版本 | 安装、观察、替换/锁、导出与交接分别有结果；未测不标支持；不硬编码研究机器用户名、真实 provider 域名 |
| V-33 | 默认库、自定义完整库、应用重启、外部位置不可用、全局数据根调整 | 定位持久有效；catalog 和材料同库；位置只读，不能隐式迁移/创建空库掩盖丢失；失败保留原定位 |

观察无污染可以组合“原文件/配置哈希或内容对照、进程/网络 mock 断言、模型请求计数、消息计数”。单纯 UI 看不到新消息不足以证明后台没有模型请求。具体真实文件读取须限定受控样本。

## 4. 命令与证据

先按改动包/文件运行相关 Go 与 Vitest；涉及页签/桥接/存储等共享接口时扩展到相关回归，再按风险跑整套与前端构建。使用 DEVELOPMENT.md 的命令，不照搬其他机器路径。完整 Wails 构建和最终运行按本地规则交给用户；不能将 frontend build 称为完整桌面构建。

每条测试记录应包含：编号、测试类型（单元/隔离集成/真实应用/真实模型）、操作系统、GoNavi 提交/工作区状态、原工具版本和入口、虚构夹具范围、步骤、预期、实际、结果和可复查证据。

结果枚举：通过 / 失败 / 未执行 / 不适用。未执行写清缺少什么；不适用写清哪个能力没有声明支持，不能把普遍核心能力写成不适用以绕过交付。

## 6. 最终验收判定

核心保全、独立读取/导出、启用禁用、无污染、隐私、用户删除与失败恢复等必需能力有失败，不能验收。可选自动交接/原生窗口入口可明确降级；手动材料路径必须可用并经过用户路径检查。

真实模型召回或未具备环境的平台测试未执行时必须在交付报告中保留，不能声称已验证；是否发布该平台/入口依据实际验证与用户决定，不由模拟测试推定。

产品最终页面须交给用户人工测试。用户说“测试通过”不等于提交/推送/PR 授权；执行远程写入前仍遵循仓库流程。
