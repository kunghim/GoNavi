## 1. 产品定位与问题

### 1.1 定位（已确认）

用户将 GoNavi 定位为能够保存和管理各类资产数据的工作台。AI 编程工具的会话也是资产：它包含需求、推理过程中的可见记录、方案、操作历史、结果、附件和后续工作的线索，价值不应随原工具列表中的归档或删除而消失。

GoNavi 提供会话资产的发现、保全、查找和复用能力。执行工作仍交给 Codex、Claude Code、ZCode、WorkBuddy 等原工具，并优先利用各工具提供的 SDK、CLI 或协议接口。

本功能使用“智能体”连接分类及专用资产管理页，不与 GoNavi 自身 AI 助手的聊天共用列表、账本或会话运行机制。

### 1.2 已发生的问题（已确认）

1. 会话列表越来越多，难以判断哪些需要保留，也难以找到某个旧任务。
2. 将暂时不用的会话归档，之后清空归档；后来发现需要旧内容，已经找不到。
3. 在中转 provider 与官方 provider 之间切换后，原会话可能不出现在列表中，或可以找到却无法继续执行。
4. 同一个任务可能在不同入口、不同工具中继续，希望已保存的历史能够作为新会话上下文利用。

### 1.3 成功结果（已确认）

- 原工具删除会话后，已被 GoNavi 保存的资产仍可找到、查看和复用。
- 原会话仍在时，能够发现它，并尽可能通过原工具继续同一条会话。
- 原生续聊不可用时，能够从保存的材料选取历史，在目标工具中新建会话继续工作。
- 尽可能保全、尽可能复用；不承诺备份每次必定成功，也不承诺原生恢复或模型召回必定成功。
- 采集与备份不参与原对话，不把备份过程写入原会话的模型上下文。

## 2. 核心策略（已确认）

| 时机 | 基本策略 |
| --- | --- |
| 会话活跃 | 保存基础元数据，尽量直接利用原工具的原始记录；不默认周期复制活跃正文 |
| 原工具归档 | 保存一份最新原始材料，先保全，不立即做摘要或语义整理 |
| 原工具取消归档 | 继续使用原工具的活动源路径；保留已有备份 |
| 原工具再次归档 | 保存新的最新材料；新副本完整提交后替换、清理旧副本 |
| 原工具删除 | 保留 GoNavi 副本；确认来源删除后可整理供复用的材料 |
| 用户主动复用 | 可按需读取、整理所选历史，并交给原工具续聊或创建新会话 |
| 用户在 GoNavi 删除资产 | 才删除该资产在 GoNavi 中的副本和派生材料；不把原工具的删除意图同步成资产删除 |

“一份最新材料”指一个资产的最新完整材料集合，可能包含原始会话记录、必要的 fork 祖先前缀和附件。它不等于一个 JSONL 文件，也不要求向用户提供多版本备份库。更新时允许旧完整副本与新候选临时共存，以保障失败时旧副本仍可用。

结构识别、校验和必要依赖捕获属于保全工作；摘要、语义检索材料或用于新会话的上下文整理属于后续处理。归档阶段不能因为推迟语义处理而忽略原始材料完整性。

## 3. 首版范围与后续扩展

### 3.1 首版必需范围（需求整理）

- 接入本机可访问的 Codex 历史来源，包含项目会话与独立会话。
- 管理来源配置、会话基础索引、原始路径和独立备份引用。
- 查找、筛选、查看历史；显示来源、provider、保全状态和材料缺失情况。
- 归档触发最新原始材料备份，支持取消归档、重归档、源删除和启动后的状态核对。
- 保全 fork 的必要历史依赖，不把子文件误认成完整历史。
- 保存与复用可读历史，尽可能使用原生续聊；提供新建 Codex 会话的独立兜底路径。
- 不按当前 provider 隐藏历史资产，允许选择受支持的目标 provider 复用材料。
- 提供用户可控制的本地材料导出，便于手动复用和携带到其他设备或工具。
- 用户可删除 GoNavi 资产，并清楚知道对副本、派生材料及依赖的影响。

这里的“接入桌面、CLI、IDE”首先指发现和保全其实际本地历史。自动打开某入口、恢复该入口的列表或创建窗口是另一个能力，按接口与版本分别支持，不能由历史可读推定。

### 3.2 首版不作保证的范围（需求整理）

- 恢复原工具已经物理删除的会话 ID、原列表条目或未完成执行状态。
- 无条件跨 provider 原生续聊、随时回切 provider，或绕过原工具的历史校验。
- 原始数据从未被保存且已经消失时仍能够恢复。
- 将所有长历史、加密压缩状态和附件完整转换成任意模型的上下文。
- 恢复原工作目录、Git 分支、worktree、未提交代码和终端进程。
- 首版直接支持 Claude Code、ZCode、WorkBuddy 的完整采集与自动启动。
- 云端会话服务端恢复、远程主机持续采集、云同步或团队协作。
- 原工具对真实桌面入口执行 provider 切换的兼容性保证。

### 3.3 扩展方向（已确认方向，未实现）

后续接入 Claude Code、ZCode、WorkBuddy。设计应分别容纳“读取来源”和“启动目标”两种能力：一个工具可先支持采集或导出，不必同时具备原生恢复。跨工具复用创建新会话，不将 Codex 原生 ID 或内部执行状态伪装成其他工具的会话。

GoNavi 是跨平台产品；现有实验来自 macOS。实现须按 GoNavi 现有平台拆分检测、观察和文件提交，支持矩阵以产品实际验收填写。不得凭 macOS 实验将 Windows/Linux 或所有 IDE 标为已支持，也不得只用版本号硬编码判断整个工具不可用。

## 4. 资产与状态的产品模型（需求整理）

### 4.1 必须区分的对象

| 对象 | 含义 |
| --- | --- |
| 来源 | 一个工具在某个主机、历史根目录或入口下的数据范围；可有多个来源 |
| 会话资产 | GoNavi 管理的逻辑记录，关联原生 ID、来源和可利用材料 |
| 原始来源引用 | 原工具当前维护的会话路径、原生标识和状态 |
| 独立备份 | 不依赖原始来源继续存在的材料集合；不是原工具路径的替代写入位置 |
| 派生材料 | 从历史提取的可读消息、检索材料或用户选定的新会话上下文 |
| 复用关系 | 原资产与新建目标会话的来源关系；不同于原工具的 native fork |

原生 ID 不能单独作为所有主机和来源下的全局唯一身份。同一原始会话被多个入口发现时应尽量识别重复；材料副本不是另一个毫无关联的聊天。

### 4.2 基础信息

尽量记录原生 ID、标题、工具与入口、来源位置、项目/工作目录、创建与更新时间、历史 provider/模型配置、归档状态、fork 关系、最近观察时间、备份时间与覆盖范围。无法取得的字段标为未知，不从文件名或缺失信息猜测。

历史 provider/模型配置、最近观察到的运行配置、本次复用选择的目标配置分别表达。配置中的模型名称不保证中转站实际后端身份，旧预设不代表当前运行配置。

### 4.3 状态必须分维度表达

| 维度 | 需要表达的情况 |
| --- | --- |
| 原始来源 | 活跃、归档、明确删除、来源缺失/不可达、状态未知 |
| 入口列表 | 可见、已移除、未知；没有接口时不伪造确定状态 |
| 备份 | 未备份、保存中、待校验、已校验、更新失败、旧副本可用、材料不完整 |
| 可读材料 | 尚未整理、可读取、部分可读、缺少依赖/附件、未知格式或不透明状态 |
| 复用结果 | 未尝试、已找到、已读取、原生入口已启动、执行失败、新会话已创建、实际轮执行已完成 |

不得用一个“已恢复”同时表示读取成功、resume 请求被接受和模型执行成功。可读材料完整也不等于模型已经接收全部历史。

## 5. 生命周期规则（需求整理）

| 操作或观察 | GoNavi 应有行为 | 不应自动产生的后果 |
| --- | --- | --- |
| 启用来源，首次发现 | 建立基础索引；对现存归档补保存材料 | 不批量复制所有活跃正文 |
| 新聊天或活跃续聊 | 更新基础元数据；正文尽量按需读源 | 不向模型报告采集状态，不自动摘要 |
| 归档 | 定位实际归档源，保存最新材料及必要依赖，记录覆盖范围 | 不假定已归档记录永远不变 |
| 取消归档 | 更新活动源引用，保留独立副本；明确副本是上次归档状态 | 不把备份路径写回原工具索引 |
| 再次归档 | 新完整材料提交成功后更新 latest；失败保留旧版 | 不先删旧备份再开始复制 |
| 原始来源明确删除 | 保留资产与副本，切换为可从副本读取；可本地整理复用材料 | 不连带删除 GoNavi 资产 |
| 原始来源暂不可达 | 保留最后观测状态与备份，可由用户选择读取副本 | 不直接宣称原工具已永久删除 |
| IDE 仅移除列表条目 | 原记录仍在时继续索引、查找；未知外层状态如实标记 | 不把界面移除等同于原生归档或物理删除 |
| provider 改变 | 资产仍可查到；呈现历史配置与可选目标 | 不改写历史以伪造兼容，不自动改变正在运行的全局配置 |
| 原工作目录移动或消失 | 会话材料仍保留；启动时允许另选目录并提示差异 | 不将聊天备份视为项目文件备份 |
| 监听中断、应用重启 | 核对现存源、备份和未完成保存；补办仍能完成的工作 | 不宣称可补回从未保存且已消失的材料 |
| 禁用智能体或单个来源 | 停止相应后续采集，保留入口、配置及资产；重新启用补核对 | 不默认清空副本，关闭页签不禁用 |
| GoNavi 删除资产 | 清理该资产的索引、副本和派生材料；不因扫描立即重新出现 | 不默认删除原工具的聊天 |

fork 子资产仍引用某些祖先材料时，删除父资产不能静默破坏子资产。需要保留或转移子资产必需的材料，并让用户理解删除范围；物理存储与删除交互在技术、交互方案中细化。

| FR-27 | P0 | 每个本地 GoNavi 数据根内每种工具只有一个入口；重复启用幂等，多个入口/历史位置在工具内部管理 |

## 7. 备份、材料与失败约束

### 7.1 完整性

- 独立材料应保留原文、来源与版本信息、必要依赖和校验信息。保存成功与材料完整性校验成功分开表达。
- fork 按分叉点的固定边界保留祖先历史，父会话后来追加的内容不得混入子资产。
- 祖先仍活跃时，可以在子资产归档事件中捕获子资产必需的固定祖先前缀；这是必要依赖保全，不是周期复制祖先聊天。
- 附件仅存路径不等于附件已备份。外部附件在归档前已丢失时应标明缺失；内嵌图片不保证等同于上传文件的原始分辨率和元数据。
- 加密压缩状态仍原样保留，不宣称可解密或转换成跨工具的明文摘要。若原始可读消息也在，可单独复用它们。
- 项目代码、Git 状态和工作目录本身不随会话自动备份。

### 7.2 覆盖边界

- 不把“归档后没有继续聊天”当作文件绝不会变化的保证；保存遇到变化时须重试或明确未完成。
- 只在归档保存，意味着取消归档后新增但尚未再次归档的内容可能不在 latest 中；明确显示备份时间和范围。
- 归档后立即删除存在竞态；应尽可能提高成功率，但不宣称可以消除全部丢失窗口。
- 监听停机期间归档且删除、没有任何旧副本或完整暂存材料的情况不可恢复。
- 仅发现文件缺失不足以区分删除、目录移动和主机不可用；不以推测的永久删除触发破坏性操作。

### 7.3 失败后的结果

磁盘不足、权限变化、进程退出、原始变化、校验失败或依赖缺失时，必须能够区分“没有副本”“旧副本仍可用”“新候选未提交”“材料部分可用”。失败不得变成无声成功。

保留一份最新材料不妨碍短暂暂存与恢复待办；已提交副本的替换与候选清理必须可以在重启后判断。具体事务、调度和持久化结构留到技术方案。

## 8. Provider 与复用规则

### 8.1 查找和继续使用

provider 是来源和启动配置，不是资产可见性的边界。同一个历史目录可以出现多个 provider 的记录，查询时不能只保留当前 provider。

找到记录、读取成功、原生 resume 被接受、实际下一轮完成是不同结果。不能通过修改 provider 字段、历史消息 ID 或原工具索引来伪造兼容。

原生继续使用尽量沿用原工具认可的环境和权限机制；GoNavi 不复现编码代理的执行引擎。无法恢复原列表时，可从受支持入口继续利用记录，不保证所有入口共享外层列表状态。

### 8.2 跨 provider

用户可选择目标 provider 新建会话，利用保存的可读历史。更换 provider 不应默认影响用户正在运行的其他会话，也不要求用户先切换当前桌面全局配置才能导出材料。

跨 provider 原生续聊可能写入原记录并影响再次回切。首版不提供跨 provider 原生尝试，以携带可读材料新建为路径；同 provider 原生继续按实际能力提供。不得改写历史字段伪造兼容。

认证和历史资产分开处理。尽量复用原工具已有的认证与配置；不在会话备份中复制 auth.json、完整 provider 凭据或用户密钥。会话原文本身可能含敏感内容，完整保存策略不能被错误理解为备份所有认证文件。

### 8.3 新会话利用历史

- 用户知道目标工具、provider、工作目录、历史范围和即将传递的材料。
- 旧对话作为资料，旧工具调用作为事实记录；不自动重跑历史命令。
- 旧项目路径、AGENTS 指令和权限设置不自动成为新环境的指令或授权。
- 新会话有新原生 ID；保留来源关系，不覆盖原资产。
- 接口只接受创建时，显示“已创建”；没有实际执行证据时不能显示“续聊验证成功”。
- GoNavi 不为日常状态检查自动发送模型轮或制造业务对话；摘要生成和对外传递由用户主动发起的动作决定。

## 9. 非功能要求（需求整理）

1. **无上下文污染**：索引、复制、校验、重试不通过对话消息、模型工具调用或工具输出注入原会话。不能以要求模型自己备份作为后台保全方式。
2. **原工具优先**：观察与读取不改写原工具私有数据库；会话操作优先调用受支持 SDK、CLI、协议。能力不足时降级为导出或明确操作说明。
3. **响应与资源**：列表和元数据操作不必等大型正文解析完成；大型材料复制、查看和处理须有进度或状态，不长时间阻塞原聊天使用。
4. **本地边界**：采集、原文保存和基础整理默认本地进行；不会自动将历史发送给模型、云服务或第三方同步服务。
5. **凭据与日志**：凭据按现有安全存储机制处理；错误、诊断及日志不得泄露正文、密钥或认证信息。首版按本地原始材料文件和平台用户权限保护设计，不新增资产加密功能，界面不宣称已加密；不绕过已有 secretstore。
6. **兼容与未知格式**：未知字段保留；不能解析时可保存原文并标明局限，不把解析失败误报成空会话。支持能力与工具、入口、版本分别关联。
7. **扩展性**：采集、材料解析、原生继续、新建和导出能力可以分别扩展；其他工具不能默认继承 Codex 的支持状态。
8. **可解释性**：用户能够知道当前读自哪里、哪次材料有效、遗漏什么、失败原因和下一步可做什么。

不承诺固定 1–3 秒复制成功率、固定数据丢失上限或所有设备必定恢复。可量化性能指标待首版平台和运行方式确定后制定；已有本机耗时仅用于工程判断。

## 10. 典型用户流程与验收

| 编号 | 用户场景 | 首版验收结果 |
| --- | --- | --- |
| AC-01 | 项目内外会话太多，某条仍在但找不到 | 在已纳入来源中按元数据找到，识别真实位置和历史 provider；不受当前 provider 过滤 |
| AC-02 | 归档暂时不用的会话 | 自动保存最新原始材料，显示保存/校验状态；不新增原聊天消息或模型备份工具调用 |
| AC-03 | 取消归档继续工作，然后再次归档 | 取消归档后使用活动源；旧备份保留；再次归档后最新完整材料更新，正常只保留一份 latest |
| AC-04 | 清空原工具归档，后来想找旧内容 | 已保存资产仍可找到；源不存在时只用独立副本读取、导出或新建会话，不依赖原索引残留 |
| AC-05 | 一次保存失败或进程中途退出 | 旧完整副本不受损；失败或未完成状态可识别；源/完整候选仍在时重试或启动恢复有效 |
| AC-06 | 多方向探索形成多层 fork，之后删除来源 | 保存完整依赖；在全链原始材料移除的受控测试中，仍能提取正确分支历史，不混入父会话后续修改 |
| AC-07 | 从中转改用官方，原生执行失败 | 资产可见；报告失败阶段；可将可读材料交给官方新会话，自动路径按验证能力开放，否则提供有效手动材料；真实召回/续聊仅在具备受控测试条件时验证并据实记录 |
| AC-08 | 长会话包含压缩、工具调用和图片 | 原文与必要内容保留；压缩、可读消息、工具对和附件可用性分别识别；预算限制和不可移植内容如实说明 |
| AC-09 | 在支持的原工具入口重新打开旧会话 | 尽可能原生继续；原生 ID 与执行结果可核对。不能自动打开某入口时提供可用兜底 |
| AC-10 | 用户删除 GoNavi 资产 | 副本与派生材料按说明清理，相关子资产不被静默破坏；重新扫描不自动让该资产复活 |
| AC-11 | 来源目录移动、磁盘未挂载或主机不可达 | 显示来源不可用而非未经确认的删除；已有副本仍可利用；工作目录可在复用时重新选择 |
| AC-12 | 旧预设还是 DeepSeek，目标当前已是 GPT | 历史配置保留，但启动与显示以本次实际目标为准，不因旧预设错误路由或覆盖运行配置 |
| AC-13 | 新建连接选择 Codex，检测未通过或已启用 | 未通过给出准确原因、定位与重检；已启用显示打开管理，不建立重复入口 |
| AC-14 | 启用后关闭页签、禁用、重启、重新启用 | 页签与保护独立；禁用保留资产；重新启用沿用同一入口，不能把停机期间未保存且已消失的历史说成已补回 |

原生续聊的成功不是首版所有环境必须实现的硬保证；明确降级、可读材料导出与受支持入口的新建复用是必须提供的兜底结果。实验只证明所测样本中的召回，不承诺新模型记住任意历史细节。
