# 开发任务与阶段交付

- 版本：v1.0，2026-10-06；产品范围以 [交接入口](README.md) 为准。
- 顺序：M0 → M1 → M2 → M3 → M4 → M5 → M6。每阶段有可验收结果；仍需做完适用 P0，不以最小检查点代替全部交付。
- 所有状态初始为“未开始”，由实际开发者更新本地进度；本次交接文档推送不授权产品代码提交或 PR。

## M0：实现前核对与集成方案

产物：本地实现记录，包含当前分支/基线、涉及文件、工具环境、拟支持平台与入口、适配读取方法、观察实现、材料库结构和最终交接方式。只检查相关模块，不全量扫描私人历史。

- 阅读目标工作区已有 AGENTS.md/贡献规则及可用本地任务流程，从最新 upstream/dev 建独立产品功能分支；保留交接工作区查阅文档，不带入交接提交；先检查用户已有改动。
- 核对新建连接分类、Sidebar 节点与动作、页签类型/上下文/持久化、appdata、Wails 生命周期和已有 secretstore。
- 选择跨平台观察依赖及平台提交/锁实现，给出依赖影响；不用 shell 定时复制活跃聊天代替。
- 针对安装版本核对 Codex 格式及官方协议，明确只读读取方式、来源去重和默认 provider 过滤的规避方式。
- 验证官方终端交接最小方案；没有合适启动入口时保留手动导出方案，不在 GoNavi 内加代理运行页面。

完成条件：能把方案逐项对应到冻结范围；工程待验证列明；普通拆分可自行决定。只有必须扩大范围时向用户说明，不能以环境未齐为理由重新讨论全部产品。

## M1：独立领域与持久化基础

覆盖：FR-01、12、13、20、27、29 的基础；AC-05、10、14；验收 V-01、09、11、12、13、14、20、21。

- 建立 Integration、Source、Asset、SourceReference、CaptureJob、MaterialManifest、HandoffPlan 等领域模型，源状态与副本状态拆开。
- 适配器只定义必要能力，Codex 首个实现；不扩大 db.Database，不把 agent 塞进数据库 host/port/user。
- 独立 SQLite 索引与材料库定位配置，版本迁移、唯一工具约束、多个来源与稳定资产身份。
- 自包含原始材料、候选提交、latest 指针、启动核对及用户删除抑制标记；库写入锁。
- 文件与数据库双持久化的恢复规则明确；只读状态投影可重建，用户设置/删除标记不能丢弃。

完成条件：纯虚构材料的正常提交、旧副本保留、五类故障、删除与候选并发都有有效测试；不能先用不安全覆盖上线再补事务。此阶段可以没有 UI。

## M2：检测、启用与主页接线

覆盖：FR-01、26、27、28、29；AC-13、14；验收 V-01 至 05、18、30。

- 分类增加智能体，全部/搜索可找到 Codex；未实现工具不作为可选支持项。
- Detect 返回安装/版本证据、可读历史位置和独立交接能力；不发送 hello，不遍历正文。
- 明确未安装、未初始化、无权限、未知格式、IDE-only、已启用、已禁用；位置修改使检测结果失效，重新检测后才能启用。
- 初次启用校验后端当前条件并幂等，观察启动失败不能显示保护正常。
- 固定系统分组和唯一工具页签、禁用保留、关闭页签独立、重新启用沿用原入口；存量数据库节点、排序和菜单不回归。
- 页签上下文、会话 slice 与 Wails 桥接按模块拆分；不使 SQL/DB 操作误用智能体 ID。

完成条件：真实 GoNavi 页面走通上述状态，不用静态假成功数据替代；数据库功能回归通过；启用后已有归档的索引/保全可异步观察。

## M3：Codex 发现、归档保全与状态同步

覆盖：FR-02、05 至 13、21；AC-01 至 06、08、11、12；验收 V-06 至 19、22、27。

- 只读来源元信息，项目内外、活动/归档均发现，当前 provider 不隐藏旧记录；实际目录和版本识别。
- 元数据增量更新；活动正文按需读取，不做周期全量复制、解析或持久全文索引。
- 文件观察覆盖根目录/归档变更及必要目录更新；持久化归档保存意图，事件重复不重复创建任务。
- 首次启用、重启、重检和事件遗漏时补核对；源归档后立即复制，不故意等待语义处理。
- 保全多层 fork 固定祖先前缀、附件与未知项，复制时检查源变化；原源暂不可达与明确删除分开。
- 调度同资产串行、代次取消与预期旧版本；不能让延迟任务覆盖新 latest 或复活已删除资产。
- 取消归档保留备份，重归档成功再替换；失败显示旧覆盖范围；停止应用不宣称继续采集。

完成条件：隔离目录的完整生命周期走通。首个产品检查点是：启用 → 发现 → 归档 → 保存 → 移除隔离原源 → 用独立副本读取；全部 hash/范围/源状态可核对。此检查点不能替代 M4–M6。

## M4：资产阅读、查找、导出与删除

覆盖：FR-03、04、18、19、20；AC-01、04、08、10、11；验收 V-07、15、16、17、19 至 24、30。

- 元数据筛选、排序与分页：来源、项目/目录、时间、provider、原源/备份状态；不伪称全文搜索。
- 详情明确读源与覆盖时间，按需加载可读消息、成对工具记录、材料及缺失附件；未知项保留原文导出。
- 正文内查找按需，不持久化活跃全文；长历史不一次加载/渲染整个文件。
- 导出自包含原始材料集合或选定可读资料，携带来源、版本、范围、完整性清单；不带认证文件。
- 单项 GoNavi 删除确认、持久化抑制、候选取消及文件清理；父资产删除不破坏子资产固定材料；失败未清理可见。
- 禁用或卸载后仍可看已有资产；只有元数据而无正文时给出准确空态，不制造恢复会话。

完成条件：源记录不存在时 UI 与导出无需原数据库/目录；导出物经独立读取校验。删除后重启扫描不会自动回来，仍保留的子资产材料有效。

## M5：原生继续与跨 provider 新建交接

覆盖：FR-14 至 18、21、22；AC-07、09、12；验收 V-25 至 29。

- 能力判定控制“继续原会话”与“携带历史新建”；同 provider 原生尽力，跨 provider 明确新建。
- 两阶段选择/预览；历史引用、当前请求、工作目录、provider、附件及省略范围明确。
- 首版默认最近可识别完整讨论，无法识别时最近可读轮次；支持明确选择范围，不用模型自动猜测或摘要。
- 目标预算未知时不造精确 token 数；已知超限时缩小范围或导出，不静默截断。
- 实际启动不改全局 provider/认证文件，不把完整原文或凭据暴露在命令行/日志中；旧预设不覆盖当前目标。
- CLI 优先；官方可交互交接验证后才能开放自动路径。未支持时交付可用材料和准确步骤，状态为准备材料；不做内置代理界面。
- 结果区分材料已准备、入口已启动、会话已创建、轮执行已完成；实际失败保留选择并允许显式降级。

完成条件：手动交接必需；自动路径有入口及原生 ID 等证据才标可用。没有真实模型测试条件时报告未执行，模拟测试不能证明模型召回；不主动替用户切当前桌面 provider。交接失败不能降级为更改全局配置。

## M6：完整验收与交付记录

覆盖：全部适用 P0 / AC-01 至 14；验收 V-01 至 33。

- 按 [验收清单](acceptance.md) 填写通过、失败、未执行、不适用及依据；不得只汇报构建成功。
- 检查关闭应用、禁用、来源断开、磁盘不足、写到一半退出、库锁占用、旧任务竞争和平台差异。
- 六种语言同步、键盘操作、窗口尺寸、真实 GoNavi 页面、数据库回归；无新增 UI/状态库与手改生成绑定。
- 相关 Go/Vitest 完成后按跨模块风险扩展验证；用仓库指定流程准备用户人工测试。完整 Wails 构建/运行按本地规则由用户完成。
- 交付本地实现摘要、变更范围、支持矩阵、已知限制及用户测试入口；等待用户测试和另行提交授权。

完成条件：没有适用必需项失败；未执行项准确列出、不能当作已支持。P1 与未确认扩展没有混入。状态中仍有核心未完成工作时，报告阶段结果，不宣称全功能完成。
